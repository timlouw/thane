# Changelog

All notable changes to this project will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

Three sets of changes: the fixes found by porting a real Angular site (routing, forms, Firebase) to Thane; a simplification and hardening round over the whole framework (see Internal), which also narrows the public API to what apps use and changes the compiled output; and a round that makes templates terser and silent failures loud (JavaScript control flow, refs, slots, `bind:`, `class:`, event modifiers, ownership, typed template values, new build errors), mounts routing through `mount()`, and makes `thane dev` keep the page's state through hot updates. Components compiled by an earlier version must be rebuilt.

### Breaking

- **`whenElse()` is gone: `when(condition, then, else?)` is the one conditional.** In content, `when()` takes one or two templates, and shows nothing while the condition is false when it has one; in a tag, `when(condition)` alone shows the element. Replace `whenElse(c, a, b)` with `when(c, a, b)`. A content `when()` with only a condition, more than three arguments, or a branch that is not a template is a build error (THANE014).
- **`repeat(items, row, { key, empty })`.** The key and the empty template are options, written in the call as an object literal: the key is a property name (`'id'`) or a function of the item, and `empty` a template. Anything else as the third argument, an option `repeat()` does not have, or a fourth argument is a build error (THANE010).
- **Routing is mounted by `mount()`, and the router's functions are imported.** `mount(App, { routes })` mounts a shell whose template holds a `<router-outlet>`, where the pages go (a shell without one uses the page's own, and `mount()` throws when there is none); `mount(Routes)` mounts the routes alone. The `router` option, its `outletId` and the `#router-outlet` element are gone, and so are the globals `navigate`, `navigateBack` and `currentPath`: import them from `thane/router`.
- **`mount(component, { target, props })`** replaces `mount({ component, target, props })`. Anything that is neither a component nor routes is "Invalid mount component".
- **A `computed()` is not a `Signal`.** `Signal<T>` carries a brand that `ReadonlySignal<T>` lacks, so a `computed()` or a read-only signal where a `Signal<T>` is asked for (a prop the child writes, `bind:value`) is a type error.
- **Template values are typed, in the type check** that `thane build`, `thane dev` and `thane typecheck` run, and in the editor: in content a value is text, a number, a boolean, nothing or templates; in a tag text, a number, a boolean or nothing; an event expression is a handler for that element's event, or a call that runs on it. An object (`${user()}`, which rendered `[object Object]`), a promise, a signal without its call, and an event expression whose value is a function (which nothing would call) are type errors where they are written. A ref is checked against its tag, and a `bind:` signal against its field.
- **New build errors for code that did nothing, or the wrong thing, without a word:**
  - an unknown event modifier (`@click.prevnet`, with the modifier it is close to), or `.passive` with `.prevent` (THANE015): an unknown one was dropped;
  - a `${…}` alone in a tag that is not `when()` or a ref (THANE016): it stayed in the markup as text; and a ref in a list row;
  - a `bind:` other than `bind:value` and `bind:checked`, or a `class:name` without a condition (THANE017);
  - `found?.()` in a binding, where `found` is a value that may be missing (THANE018): the binding subscribed as the component mounted, and threw for a missing one;
  - two components of a build with one selector (THANE013, which was a warning): they shared their host class, its styles and its hot swaps;
  - a second return in a setup, of an object or of a template alone (THANE412): every branch rendered the last;
  - lint rules THANE414 (a signal without its call in a template), THANE415 (a key of the setup's return object that nothing reads, with the key it is close to, such as `onMoun`) and THANE416 (a warning: a prop whose value reads a signal passes a snapshot).
- **`defineComponent()` throws when it runs uncompiled.** It rendered a string template through `innerHTML`, without bindings or ownership, so a component the compiler did not compile showed static markup. Every compiled component is registered by `__registerComponent` or `__registerComponentLean`.
- **THANE401 (component-property-order) and THANE402 (lifecycle-arrow-function) are retired**, and their codes are not reused: the order of a component's keys never mattered, and a hook may be written in any form. A re-export of a component (`export { Card } from './card.js'`) passes THANE409.
- **The type sync no longer removes the generated files of earlier versions** (`__thane-router.generated.d.ts`, `.thane/router-types`). Delete them by hand if a project still has them.
- **An `html` template is a `Fragment`, a type `thane` exports.** `html` returned `any`, and a component call `string`: both are now `Fragment`, which has no members, and a component's `template` takes a `Fragment` (the compiler compiles nothing else there), so `template: '<p>…</p>'` is a type error. `when()` returns a `Fragment` and takes a `Fragment` or a plain template literal as each branch (a number there is a type error); `repeat()` takes one as the row and the empty template. Code that used an `html` template as a string no longer type-checks.
- **`thane` exports what apps use, and nothing else.** It keeps eleven values (`signal`, `computed`, `effect`, `batch`, `untrack`, `onCleanup`, `defineComponent`, `mount`, `unmount`, `registerGlobalStyles`, `ref`), the template markers (see the next entry) and eight types (`Signal`, `ReadonlySignal`, `ComponentContext`, `ComponentHTMLSelector`, `MountHandle`, `RoutePaths`, `Fragment`, `Ref`). Removed, with the migration:
  - `mountComponent`: call `mount(component, { target, props })`. The compiler still turns a component-only `mount()` into `mountComponent`, now imported from `thane/runtime`.
  - The `html` and `css` runtime string shims: `html` and `css` are now template markers, compiled away.
  - The types `ComponentRoot`, `ComponentReturnType`, `MountOptions`, `Route`, `RouteComponent`, `LazyRouteComponent`, `EagerRouteComponent`, `RoutesMap`, `RoutesConfig`, `RegisteredRoutes`, `RouterConfig`, `ScrollRestorationConfig`, `ExtractRouteParams`, `RouteToPath`, `RouteContextForSelector`, `UntypedRouteContext`: TypeScript still infers each of them where you write the object, and editors still show them in hovers; where you need a name, write `HTMLElement` for `ComponentRoot`, `Parameters<typeof mount>[0]` for `MountOptions`, or the shape itself.
  - `Register` and `RouteComponentRegister`, the targets of `declare module 'thane'` augmentation: route typing comes from the generated `.thane/types` files, which augment the global `ThaneTypeRegistry`. Delete any hand-written augmentation.
- **The template markers are imported from `thane`:** `import { html, css, when, repeat } from 'thane'`. They were globals, so a file that uses one without the import is now a type error ("Cannot find name 'html'"). They still exist only at build time: the compiler turns each use into DOM code, and none of them reaches a bundle. The compiler finds them by name, so a renamed import (`html as h`) or one read through a namespace import is never compiled: it is a build error (THANE413, which also covers `defineComponent` and `ref`). The router's functions are imported from `thane/router` too; none of them is a global.
- **`thane/router` exports the router's functions only:** `defineRoutes`, `navigate`, `navigateBack`, `href`, `currentPath`, `isActive`, `markActiveLinks`, `setMeta`, the search parsers and the head-field helpers. `matchRoute`, `startRouter` and `stopRouter` (internal) and every type (`RouteParamNames`, `RouteParamsObject` and the router types above) are gone from it.
- **`thane/compiler` and `thane/compiler/cli` are removed.** They re-exported the compiler's internals. Build with the `thane` CLI and `thane.config.json`.
- **The compiled-output contract changed.** Compiled code now finds every node by a path computed at build time, and compiled templates carry no ids: `__bindIf(start, end, signal, template, initNested)` and `__bindIfExpr(start, end, signals, evalExpr, template, initNested)` work over two comment anchors, `__b(ctx, elements)` receives the template's elements, list anchors and child placeholders are comments, `createKeyedReconciler`'s batch argument is built by `__batchRows`, and templates are built by `__T`. Components compiled by an earlier Thane version, for example shipped pre-compiled in a library, must be rebuilt with this one. [Contracts](docs/contributing/contracts.md) describes the contract.
- **`repeat()`'s options are checked (THANE010), and its type takes them:** see `repeat(items, row, { key, empty })` above. A key function passed where the empty template went used to become the empty template's markup, the list was keyed by index, and emptying it threw a `TypeError`.
- **A `repeat()` empty template must be one static element (THANE011).** It is inserted as one element while the list is empty: only a first element was ever shown, text alone threw when the list emptied, and a `${…}` in it was shown as written. Wrap the content in one element, and put an empty state that changes in a `when()` next to the list.
- **THANE406 (`no-element-id`) is retired.** Compiled code no longer uses ids to find anything, so an `id` of the form `b0` cannot collide with anything. The code is not reused.
- **`--app` and the `app` config key are removed.** They had no effect. `--app` is now an unknown flag, which prints a warning, and the word after it is read like any other argument: `thane --app dev` runs `dev`. Remove `--app` from scripts.
- **CLI flags that take a value follow one rule, with or without a config file:**
  - a value flag never takes a following flag as its value: `thane dev --host --open` is a bare `--host` and `--open` (without a config file, `--entry --prod` used to set the entry to `--prod`);
  - a bare value flag stands for its fallback even when a config file sets the option (it used to keep the config file's value): bare `--host` is `0.0.0.0`, bare `--port` is `4200`, and `--base`, `--target`, `--env-prefix` and `--legal-comments` fall back to their defaults;
  - `--port` accepts digits only: `--port abc` (which gave `NaN`) and `--port 3000x` (which gave 3000) stop with an error;
  - an argument that is neither a command nor a flag's value (`thane biuld`) prints "Unknown command"; the build then runs as before.

- **Template event handlers are typed in the type check** that `thane build`, `thane dev` and `thane typecheck` run (see Added). Code that relied on the handler's parameter being `any` is now a type error there, for example `@input=${(e) => query(e.target.value)}` (`e.target` is an `EventTarget`): write `e.currentTarget.value`, typed as the element, or `bind:value`.
- **A route's `title` moves into `meta`:** `'/about': { component, meta: { title: 'About' } }`. `meta` holds every head field a route sets (see Added). A route with `title` at its top level is a type error.

### Added

- **JavaScript control flow in templates.** In content, a ternary, an `&&` and a `.map()` of templates compile to the directive they mean: `${open() ? html`…` : html`…`}`, `${error() && html`…`}`, `${items().map((i) => html`<li>${i.name}</li>`)}`, chains of ternaries too. See [Templates](docs/templates.md#javascript-control-flow).
- **`when()`'s narrowing form:** `${when(user(), (u) => html`<p>${u.name}</p>`, html`<p>Signed out</p>`)}`, its parameter typed without `null` and the other falsy types. The compiler reads the function's body as the branch, so its bindings follow the condition. A signal that may be missing is a condition: `when(found, (s) => html`…${s().title}…`)` subscribes to it only while there is one.
- **Element refs:** `const input = ref<HTMLInputElement>()` in the setup, `<input ${input}>` in the template, and `input.el` is the element from `onMount` on; in a `when()` branch, `null` while it is hidden. No query: the compiled code assigns the element from its path. A ref's type is checked against its tag.
- **Slots.** A prop typed `Fragment` takes a template the parent writes, `Panel({ body: html`…` })`, compiled in the parent (its bindings and handlers are the parent's) and placed by the child as `${props.body}`; one the parent leaves out renders nothing. See [Components](docs/components.md#slots).
- **`bind:value` and `bind:checked`:** `<input bind:value=${email} />` shows the signal and writes what is typed back into it (`change` for a select and a checkbox). **`class:name=${condition}`** toggles one class next to the element's static ones.
- **Event modifiers:** `.prevent`, `.stop`, `.self`, the key guards (`.enter`, `.esc`, `.tab`, `.space`, `.delete`, the arrows), `.once`, `.passive` and `.capture`, in any combination. `.self`, `.once`, `.passive` and `.capture` give a row's element a listener of its own.
- **A component owns what its setup creates.** A `computed()` or `effect()` created in a setup or `onMount` is disposed when the component is destroyed, after `onDestroy`; `onCleanup(fn)` there runs `fn` then. An effect's function may return a cleanup, run before its next run and when it is disposed, and owns what its run creates. A component whose setup may create none of these keeps the lean factory, so an app of such components bundles no ownership code.
- **A setup may return its template alone:** `defineComponent(() => html`…`)`, the same as returning `{ template }`.
- **A component without required props is called without arguments,** `Nav()`; `css` is typed as a string.
- **`isActive(pattern)`** in `thane/router` says whether the current path is a route's, or below one (`'/work/*'`), and a template that calls it follows the path: `class:active=${isActive('/about')}`. **`markActiveLinks()`**, called once, gives the document's links to the current path `aria-current="page"` each time a page is on screen.
- **`thane init [dir]`** creates a project (package.json with its scripts, a tsconfig that extends `thane/tsconfig.json`, index.html, the entry and an app component), and **`thane generate component <name>`** a component in a folder of its name. Neither writes over a file. **`thane/tsconfig.json`** holds the strict options, the editor plugin and the folders a project's code is in.
- **Hot updates in `thane dev`.** The open pages update in place instead of reloading. A changed component file is swapped: each instance is mounted again with the new code and styles, in its place, with its props, and with its state: each `const` signal of its setup and its file starts from the old one's value, and the children it mounts from the old children's. A changed store, helper or stylesheet file runs again with every module that imports it, up to the component files, and a store keeps its signals' values. A change that reaches the entry reloads the page. A development bundle holds of each package only the bindings the app imports (router-app: 72,017 → 48,726 B). A production build is unchanged: the hot runtime runs only in a page the development server serves. See [CLI](docs/cli.md#thane-dev).
- **`lint` in `thane.config.json`** sets each lint rule's and compiler warning's severity: `"off"`, `"warning"` or `"error"`.
- **Fragments shared across files.** A module can export a fragment, `` export const Badge = html`…` ``, and other modules' templates use it wherever a fragment of their own goes: as `${Badge}`, a `when()` branch or a `repeat()` empty template, in rows and branches too. A fragment without `${…}` is written out in place. One with expressions is compiled in its module into a template and a binding function, which reads that module's signals and mounts its components; each use mounts a copy (`__mf`, a new `thane/runtime` helper). A fragment no template uses is left out of a production bundle. THANE410 (`no-cross-file-html-template`) is retired, and its code is not reused. See [Templates](docs/templates.md#fragments-shared-across-files).
- **Several components in one file.** Each `const X = defineComponent(…)` of a file is compiled on its own: its template, bindings, styles and registration, and the initial values of its own signals. A component the file does not export is private to it: the file's other components mount it like any child, and its selector is derived from its name like an exported one's. THANE407 (`single-component-per-file`) is retired, and its code is not reused. See [Components](docs/components.md#several-components-in-one-file).
- **THANE013 reports two components of a build with one selector**, such as two private `Row` components in different files, as a build error (see Breaking). They would share their host class, its styles and its hot swaps.
- **A TypeScript plugin for the editor, `thane/ts-plugin`:** the template event handler types the build's type check gives (the event, and `currentTarget` outside a row) now show in the editor too: hovers, completions and signature help inside a handler, and its errors. A tsconfig that extends `thane/tsconfig.json` has it; otherwise add `"plugins": [{ "name": "thane/ts-plugin" }]` to `compilerOptions`, and in VS Code use the workspace's TypeScript. It keeps a second language service over the sources with the handlers typed and maps every position back; everything else is the editor's own service.
- **`currentTarget` is typed as the element**, in the type check, for a template event handler outside a list row: `<input @input=${(e) => query(e.currentTarget.value)} />` type-checks, `e.currentTarget` being an `HTMLInputElement`. A row's handler is delegated to the list container, so there it stays `EventTarget | null`.
- **Typed search parameters.** A route's `search` schema names the query parameters its page reads, each with a parser: `searchString()`, `searchNumber(1)`, `searchFlag()`, `searchOneOf(['price', 'name'], 'name')` from `thane/router`, or any `(raw) => value` function. The page reads the parsed values on `route.search`, typed from the schema (a function's value from its return type annotation), and `href()` and `navigate()` take the declared values next to the path parameters and write them into the query; an undeclared one is a type error. A path with a query or a hash (`navigate('/products?page=2')`) is now a `RoutePaths`; a static path with a query used to be a type error. A production build leaves the parsing and writing out when no route has a schema (+16 B raw then); an app with one pays about 460 B raw, 200 B gzipped, the helpers it imports included.
- **Plain links to routes navigate in the app.** A click on `<a href="/about">`, or `href=${href('/users/:id', { id })}`, is taken by the router instead of loading the page again. The browser keeps a click already handled (`@click.prevent`), a modified click or another button, a link with a `target`, `download` or `rel="external"`, a link to another site or to a hash on the page, and a link to a path no route has (a file). A production build leaves this out when no template and no `index.html` has a plain link to a path; an app that has one pays about 565 B raw, 220 B gzipped.
- **Route redirects and guards.** `'/old': { redirectTo: '/new' }` (or a function of the route) sends a path elsewhere, replacing the history entry. `canEnter(route)` on a route decides before its chunk is fetched: `true` enters, a path redirects there (`() => signedIn() || '/login'`), `false` keeps the page on screen and shows its URL again (on the first load, the `notFound` route). It may be async; a newer navigation wins. Both paths are typed as `RoutePaths`, and a loop of redirects stops after 10. A production build leaves the step out when no route uses either (it reads the route table); an app that uses them pays about 530 B raw, 185 B gzipped.
- **An error route:** `defineRoutes({ …, notFound: {…}, error: { component: ErrorPage } })` is shown when a page's chunk fails to load or its component throws while mounting, with what failed on `route.error` (typed `unknown`); the URL stays the failed page's and the error route's head applies. Without one the outlet stays empty, as before. A reload is the way back from a failed chunk, which the error page can offer. It costs about +125 B raw, +60 B gzipped in an app that bundles the router.
- **`@keyframes` in a component's styles are scoped to the component.** `@keyframes spin` in the `card` component becomes `card-spin`, and so does every `animation` or `animation-name` in its stylesheet that names it, so two components can each define a `spin`. An animation the stylesheet does not define (a global one) and global stylesheets keep their names. The scoping code (about 300 B raw, 135 B gzipped) is bundled only in apps whose stylesheets define keyframes; the compiler turns it on from the module whose stylesheet defines them.
- **A public folder:** the files in `./public` (or `--public <dir>`, `publicDir` in the config) are copied to the root of the output on every build, and watched by `thane dev`: `robots.txt`, `sitemap.xml`, `favicon.ico`, a web manifest, `.well-known/`. A file the build writes wins; a root `index.html` there is not copied, with a warning. When `--assets` is `./public`, there is no default public folder.
- **Route heads, typed, in the router.** A route's `meta` sets the document head while it is active: `title`, `description`, `image`, `canonical`, `robots`, `type`, `siteName`, `locale`, `twitter` and `jsonLd`. The Open Graph and Twitter tags that search engines and link previews read are derived from them, and canonical and image URLs are made absolute with the site's `siteUrl` (with a slash at the end when `trailingSlash` is set). `defineRoutes(routes, { meta, customMeta })` gives the site's defaults and a `titleTemplate`, and the app's own fields: `metaName('author')`, `metaProperty('fb:app_id')`, `linkTag('alternate', { … })`, or a function from the value to tags. Routes and `setMeta()` accept them, typed. A route with parameters can compute its fields from the route, and `setMeta()` sets fields once a page's data has arrived. Tags are updated in place on every navigation, so a tag already in `index.html` is taken over rather than duplicated. See `docs/routing.md`, Route Heads.
- **Typed event handlers.** In the build's type check, a template event handler gets its event's type, as lib.dom defines it: `e` in `@click=${(e) => …}` is a `PointerEvent`, in `@keydown` a `KeyboardEvent`, with modifiers or without. A handler written for another event (`@click=${(e: KeyboardEvent) => …}`), or a reference to one, is a type error, reported at the handler. An event lib.dom does not know is typed `any`, as before. The check rewrites each handler it types for the checker only (`(handler) satisfies ThaneEventListener<'click'>`) and maps its diagnostics back to the source as written; no bundle changes.
- **Typed navigation with parameters:** `navigate('/users/:id', { id: user.id })`, and `href('/users/:id', { id: user.id })` from `thane/router`, which gives the path (`/users/7`) for an `href` attribute or a `RoutePaths` variable. The pattern must be one of the app's routes with parameters, and `params` must give each of its parameters a string or a number; each value is URL-encoded, and the page reads it back decoded.
- **A production build writes each static route's page with its head,** `about/index.html` for `/about`, for crawlers and link-preview bots that do not run JavaScript; the root `index.html` gets the head of `/`. The values are read from the source. `thane serve --prod` serves a route's own page before the root one.
- The head renderer costs about 1 KB gzipped, and a production build leaves it out when the routes set nothing but titles.
- **Signals that keep setting each other stop with a clear error in development builds**, after 500 rounds of the cascade, and later writes notify as usual; a `computed` whose subscriber sets its own source is caught too. They used to overflow the stack and could leave later writes unnotified. Production builds have no check, and are byte for byte the same (the build defines `__THANE_DEV__` as `false`).

### Changed

- **A row's code reads the row as it is now.** Handlers, subscriptions to other signals and `.self` listeners in a `repeat()` row read the row's current item and index, after the row was given a new item or moved; they read the ones it was created with. A child component in a row is mounted again only when one of its props comes out as another value (`Object.is`), so an immutable update that copies every item re-mounts only the children whose props changed.
- **A row's attribute that reads a signal of the component is written like one outside a row:** `disabled`, `checked`, `value` and `class` as their properties, and left out of the row's template. `<input type="checkbox" disabled=${off()}>` in a row was disabled in every row, and `<input class=${c()} type="checkbox">` lost its type.
- **The type check parses each source once, for the build too, and keeps its parses across `thane dev` rebuilds.** A rebuild's check of the Cybernyte port takes about half as long (126–195 ms against 297–348 ms; the first check is unchanged).
- **An `html` template written as a whole `${…}` of another is inlined**, like a const fragment. THANE404 now reports an `html` template inside another only where it would be a plain value: in a ternary, a `map()`, or any other expression that is not a directive. See [Templates](docs/templates.md#fragments).
- **A component that is not exported takes a short selector in a production build**, like an exported one.
- Compiled files with a list share one read of Node's `cloneNode` and `insertBefore`: each imports them from `thane/runtime/dom` (a new entry, for compiled code only) instead of declaring its own. An app with many files that hold lists is smaller (1,360 B raw in a test app with dozens of them, 43 B in the store example); an app with one gains about 3 B. The compiled output's contract changes: components compiled by an earlier version must be rebuilt.
- A plain `<a href>` to one of the app's routes navigates in the app (see Added); it used to load the page again. A link with its own click handler that calls `preventDefault()` is not affected.
- **The branches of a two-branch `when()` may have any number of root nodes, text included.** A branch is everything between two comment anchors, and showing or hiding it moves the whole range. A branch with several roots used to leave its extra roots on screen when it hid, and a text-only branch never toggled.
- **`:host-context(X)` works in component styles.** The compiler rewrites it to `X &`, which the runtime scoper turns into `X .my-card`: the rule applies when an ancestor matches `X`. `:host(X)` styles the component element itself. It used to produce an invalid selector that the browser dropped with its whole rule.
- **Whitespace in templates.** Content of `<pre>`, `<textarea>`, `<script>` and `<style>` in component templates is kept as written, in development and production builds (it was collapsed), and whitespace next to such an element collapses to one space. A space between a text binding and its neighbour, whether another binding, an element or a directive, is kept in rows, components and branches: `<b>Name:</b> ${name()}` rendered "Name:John" in a row, and `${a()} <b>x</b>` rendered "Ax". Whitespace-only text between two tags is condensed: removed when it holds a line break (the template's formatting), one space when it does not, so `<b>x</b> <i>y</i>` renders "x y" as a browser shows it; it rendered "xy".
- **`@import` in a stylesheet is removed at build time, with a warning.** Thane applies every stylesheet as a constructed stylesheet, and browsers ignore `@import` there; load such a file with a `<link>` in `index.html`. `@charset` is removed too, and `@layer a, b;` is written as empty `@layer` blocks, so none of them unscopes the rule after it any more.
- **New build error THANE009** for a template the compiler cannot bind reliably: markup the browser rebuilds where a binding needs a position (text directly in a table, an `<a>` inside an `<a>`, non-option content in a `<select>`), or a comment in the form of the compiler's own markers (`<!--b0-->`). THANE007 now also reports a `repeat()` row that is only a nested `repeat()`: the list could not move such a row with its inner rows.
- **`thane/runtime` is the compiler's own entry.** Compiled components import their helpers from it, including `mountComponent`, `__batchRows`, `__T` and `__nc`. Apps must not import it: it is not an API, and it changes whenever the compiled output does.
- **A `computed` read is always fresh.** Read inside a `batch()` function, or in a subscriber before the source it depends on has notified, it returned its previous value; it now computes again when any signal was written since it last computed. Its subscribers are still notified once, with the final value. Apps with signals are 8–10 B larger (raw), apps with `computed` about 30 B.
- **A path with a trailing slash matches its route:** `/about/` shows `/about`, where it showed `notFound`. A host that serves a route's own page from `about/index.html` often redirects to `/about/`.
- **Route parameters are decoded.** `/users/ada%20lovelace` gives `route.params.id` the value `ada lovelace`, as other routers do; it was `ada%20lovelace`. A segment that is not valid percent-encoding is kept as written.
- The component compiler's log label is `component-compiler` (build errors read `[plugin component-compiler]`). It was `component-ctfe`, after a compile-time evaluator that no longer exists.
- **`.css` import types come with `thane`:** a project no longer needs `"types": ["thane/client"]` in its `tsconfig.json`. A project that lists it keeps working; the declaration is in the program once, with or without `skipLibCheck`.
- **`thane dev` reloads the open pages** after each rebuild, and when an asset or `index.html` changes. The server's socket, which relayed browser errors, also sends the reload. Development files are served with `Cache-Control: no-cache`, so a reloaded page sees an edited asset (`immutable` was sent, and assets keep their names).

### Fixed

- A delegated handler in a row that read the row's index threw `ReferenceError`.
- `.once` with a key guard (`@keydown.enter.once`) removed the listener on the first key of any kind; the listener is removed once the guards let an event through.
- `import { html, type Fragment } from 'thane'` in a component file kept its `type`: the compiler rewrote the import without it, and the bundle imported a type.
- A trailing comma after a setup, `defineComponent(() => …,)`, builds; the compiler put the template argument after the comma.
- **A two-branch `when()`'s branch may be empty.** One with an empty `html` template as a branch was not compiled: the page showed the directive's source as text. An empty branch now shows nothing.
- **A fragment passed to `when()` or as a `repeat()` empty template is its markup.** `when(loading(), spinner, done)`, with `spinner` and `done` html`` consts, rendered the words "spinner" and "done". A fragment named where a directive takes a template is now inlined like one used as `${spinner}`.
- **A fragment used twice in a template is inlined twice.** The second `${spinner}` was left as an expression and rendered its markup as text. A child component in a fragment used twice is mounted in each place.
- **An inlined fragment's markup is no longer shipped twice.** A fragment whose every use is inlined is emptied, so esbuild drops it.
- A call in a template to a function the component declares is no longer taken for a signal read. `${total()}`, where `const total = () => price() * qty()`, compiled to `total.subscribe(…)` and threw; it now follows `price` and `qty`. A plain function (`${label()}`) renders once, and a helper called with arguments also follows the signals its own body reads (`${format(amount())}` where `format` reads `currency()`). The component's setup, the file's top level, and the helpers they call are looked into; an imported name called without arguments is still read as a signal, as a store's exported signal is.
- `thane dev` recognises a component file added while it runs: every rebuild scans the project again, so a child component call to the new component compiles on the next rebuild instead of after a restart. Unchanged files are not parsed again (the scan takes about 35 ms for 300 files).
- Two route tables in one project, such as two apps that share a `tsconfig.json`, no longer collide in the generated route types. Both declared the same `Register.routePaths`; under `skipLibCheck` the first table's paths silently won, so `navigate()` in the second app rejected its own paths. Each table is now an entry of its own, keyed by its file, and the paths, head fields and page selectors of all tables add up.
- `thane dev` and `thane serve` send the right content type for fonts, WebP, AVIF, GIF, icons, XML, web manifests, WebAssembly, audio and video, and a charset with HTML, JavaScript, CSS and text. An unknown extension is `application/octet-stream`; it was `text/plain`, which `WebAssembly.instantiateStreaming` and web manifests reject. woff and woff2 fonts are no longer compressed again.
- An event handler that only contains an arrow function runs as written. `@click=${remove(item.id, () => log())}` was taken for an arrow: in a list row the listener ran only `log()`, and in a component it called `remove()`'s result with the event. Only an arrow at the top of the expression is a listener now; any other expression runs on the event, as `navigate('/')` does. A function expression (`@click=${function (e) { … }}`) is a listener too, where it used to be evaluated and dropped.
- Navigating between routes no longer flashes. The router tore the current page down and then waited for the next page's chunk, so the outlet was painted empty for as long as the chunk took (about 200 ms on a first visit over a typical connection) and for one frame even when it was cached: the document collapsed to the shell and the footer jumped to the top. The current page now stays mounted until the next component has arrived, and the swap and the scroll write happen in one task; a new page is no longer painted for a frame at the previous page's scroll offset. `currentPath()` still changes as soon as the navigation starts.
- A navigation overtaken by a newer one never mounts. The guard compared the location with the last requested URL, which were equal again by the time a slow chunk arrived, so the overtaken page mounted on top of the newer one under the newer URL. Each load takes a ticket and stands down when a newer one exists. Returning to the page on screen while another page loads cancels that load and keeps the current instance and its state. The scroll action and saved position belong to the load that was started with them, and the scroll position is not persisted while the URL and the page on screen disagree.
- Production builds never edit emitted JavaScript. The template minifier used to run over every emitted file and guess which template literals were HTML or CSS from what they contained, with a scanner that could not tell a regex literal from a division: bundling the Firebase SDK silently broke Firestore's transport, and a `'\n'` separator in application code was emptied. Templates and stylesheets are now minified inside the compiler, where it emits a template or reads a `css` template or a `.css` import, so the language is known instead of guessed. esbuild is the only thing that minifies JavaScript and the emitted files are never read back, so a library cannot be affected whatever it contains and however the bundle is split, including `splitting: false`, where library and application code share one file. One-line templates and stylesheets are minified too (the output scanner skipped them).
- Selector minification works again, and is planned from the sources instead of patched into the output. It searched the output for a `selector: '…'` property that compiled `defineComponent()` code never contains, so nothing was ever renamed. Before a production build compiles anything, Thane reads the project's own TypeScript, stylesheets and `index.html` and renames a selector only when every appearance of its text is a place the compiler writes itself: the registration, the host element of a child, a tag in `index.html`, a `.selector` class in a `css` template or an imported `.css` file. Any other appearance (a route path, a `class` attribute, `querySelector`, a static stylesheet, a stylesheet imported from a package, a comment or string inside CSS) keeps the selector's name everywhere. A generated name is never one already in use, stylesheets from packages are never renamed in, and a string in a library that happens to spell a selector is not touched.
- `css` templates keep their escape sequences. The compiler re-emitted the cooked text, so `content: "\\201C"` reached the output as `\201C` inside a template literal: a syntax error for an octal-looking escape and a silently wrong character for an icon-font code such as `\\e900`. Substitutions in a `css` template are located by the parser instead of by scanning for `${`, so an expression holding a brace or a colon is never read as CSS, and a `css` template nested in a substitution is compiled too.
- A module that holds only `css` templates (shared styles) is compiled. The tag exists only at compile time and such a module was skipped, which left a call to an undefined `css` in the output. A `css` tag that a module imports from another library or declares itself is left alone.
- The CSS minifier keeps the spaces `calc(a + b)` needs and no longer turns the descendant selector `.a :hover` into `.a:hover`. Quoted strings are copied verbatim and the last semicolon of a block is dropped.
- Minifying `index.html` no longer collapses the line breaks of an inline `<script>` (a `//` comment swallowed the rest of the script) or touches `<style>`, `<pre>` and `<textarea>` content. The same holds for a `<pre>` or `<textarea>` inside a component template.
- `style="width: ${w()}px"` dropped the `px` on every update, and `margin: ${a()}px ${b()}em` compiled to two writes that overwrote each other. A declaration value with static text or several expressions is one binding written as a template literal, and a `;` or `:` inside an expression no longer confuses the declaration split.
- The entry `<script>` was not injected into `index.html` when the entry point came from `thane.config.json`: the config loader makes it absolute and it never matched the metafile's relative path.
- The dev and serve server decode request paths, so assets with spaces or non-ASCII characters in their names are served instead of 404. Containment is checked on the decoded path.
- Generated route types list the paths as string literals instead of importing `typeof Routes`. A lazily loaded page that called `navigate()` in its own template was part of its own type (TS7022) unless the loader carried a return type annotation.

- A child-component row inside a directive no longer throws `ReferenceError: __dc is not defined` when shown: each component imports exactly the runtime helpers its compiled code uses.

Event handlers in the rows of a nested list and in a row's `when()` branches, bindings inside a `when()` in a nested row, child components in a row's `when()`, and a list inside a row's `when()` were silently dropped. A row of a `Signal<Signal<T>[]>` list that tested its item in a `when()` threw `ReferenceError` when shown, and a row `when()` whose condition was true at build time rendered garbled markup.

### Internal

- A round over `framework analysis/NEXT.md`'s sections 3 and 5 and part of section 1. A component file with children is parsed once; every name compiled code declares starts with `_`; the setup's returned template, slots, refs, `bind:` and the control flow are compiled from the one parse; hot updates, the module graph they run along, and the type check's shared parses are new. Every step was measured on the in-repo benchmark: the benchmark apps' bundles changed in names only (standard 3,698 B gzip, nested 3,810 B), so no harness run was needed. Dead and duplicated code went: a compile-time evaluator whose result nothing read, a fallback copy of the binding compiler that only ran after the first had failed, a bootstrap plugin whose result nothing read, about 160 exported internal names, and the contract constants nobody imported. Compiled code finds its nodes by paths computed on a model of the browser's HTML tree construction, checked against Chromium on 496 templates, instead of by generated ids and a `TreeWalker`; that also made builds reproducible. The reconciler's batch path became a helper of its own, bundled only by apps with a batched list, and the template helpers are shared from `thane/runtime` instead of being emitted into every component file. An effect or computed disposed during its own run no longer keeps one subscription alive. Framework source went from 17,470 to 14,722 lines. The unit tests went from 470 to 1,359, and the e2e suite gained a hardening app with a probe for each defect fixed (142 tests in the Chromium projects); `bun run check:exports`, `bun run size` and output snapshots (`bun run snapshot:output`, `snapshot:compare`) check the package surface, the sizes and the compiled output. On the in-repo js-framework-benchmark harness, measured after each step, no operation of the standard benchmark got slower, and the benchmark app's bundle went from 3,812 to 3,731 B gzip.

## [0.2.0] - 2026-09-15

The first release after the September 2026 performance spike and bug audit. Breaking changes: a `:`-prefixed attribute is a build error (THANE006) instead of a literal attribute, a `repeat()` row template with more than one root element is a build error (THANE007) instead of a slow fallback, and `whenElse()` branches and `when()` content are compiled as sub-templates, which changes what nested directives inside them can do (more), not the syntax.

### Added

- `bench/`: a self-contained benchmark harness that builds the js-framework-benchmark app from the working tree, drives it in Chrome, and records the same trace-derived total, script, paint and memory metrics as the official runner. `bun run bench --label <name>` measures a build and `bun run bench:compare <a> <b>` compares saved labels with a significance test; `--interleave` measures two builds in alternating iterations for a fair A/B.

### Performance

Measured with the in-repo harness against the previous release on the js-framework-benchmark operations, both builds interleaved in one session (script time, medians): select row 0.26x, partial update 0.59x, append rows 0.83x, replace rows 0.91x, create rows 0.93x, clear rows 0.93x, create 10,000 rows 1.02x; geometric mean 0.77x. Heap after creating 1,000 rows 0.95x.

- Every write compiled into a `repeat()` row (and expression bindings at component level and inside conditionals) keeps the last value it wrote and skips the DOM write when a re-evaluation produces the same value. Creating rows no longer issues `setAttribute('class', '')` per row when the class starts empty.
- A row attribute of the form `signal() === item.<key> ? 'on' : 'off'` (also `!==`, or the operands swapped), where `<key>` is the repeat's trackBy property, is driven by one subscription on the list that rewrites only the two affected rows, instead of one subscription per row. Rows still compute the value when created.
- Sole-content text bindings in rows write `Text.nodeValue` on update, resolving the text node lazily on the row's first update; creation still uses `textContent`.
- Dynamic `class` attributes on HTML elements are written through `className`; inside `<svg>` they stay on `setAttribute`.
- Appending items to a non-empty `repeat()` list takes a fast path that creates only the new rows, and the container is no longer detached and re-attached for appends.
- Unsubscribing from a signal is constant time; tearing down a list of subscribed rows no longer moves O(n²) array elements.
- Delegated row event listeners dispatch by the row child the event came through instead of running a containment probe per handler.

A second round, measured the same way against the build above: create 10,000 rows 0.88x, append rows 0.91x, partial update 0.86x, create rows 0.97x (30 interleaved iterations), everything else the same; geometric mean 0.96x. Heap after creating 1,000 rows 0.97x. Combined with the round above, script time is about 0.74x of the previous release.

- `repeat()` rows that need no per-row cleanups (no subscriptions, nested directives or child components) are cloned in batches of 16 from a fragment built once per list, and bound and inserted per batch instead of per row.
- Those rows no longer carry an update closure. The row's record holds the last-written value per binding and its lazily resolved text nodes, and one update function per list re-navigates from the row element; rows also share one empty cleanups array. Heap after creating 1,000 rows drops by about 5%.
- Reconciling a list against an array of the same length matches rows by position before deriving keys: an identical item needs nothing, an item whose key matches the row at that index is updated in place, and only a moved row falls through to the keyed paths.
- Unsubscribing from a `computed()` is constant time, like plain signals.

A third round, measured the same way: swap rows 0.70x (0.60 to 0.41 ms), partial update 0.83x, everything else the same; geometric mean 0.94x. Across the three rounds, script time is about 0.70x of the previous release.

- Reordering a list of the same length compares each row with the item at its index before deriving a key, so a swap of two rows in a list of 1,000 costs two lookups instead of a key derivation and a lookup per row.
- The shared update function of lean rows navigates to a bound element only inside the guard of a binding that changed; an unchanged binding costs one compare.

A fourth round, measured the same way against the build above (30 interleaved iterations on the creation and update benchmarks): every operation "same"; geometric mean 0.98x. The bug fixes above cost nothing on the benchmark app, whose bundle is byte-identical through the fallback removal, developer-id and props changes.

- The keyed reconciler builds its key map lazily: creating rows no longer inserts every row into a Map; the map is built the first time an operation needs many lookups, and a handful of lookups (a selection, a swap) scan the rows instead.

### Fixed

- `repeat()` rows with an attribute binding on an item element, such as `<tr data-id=${item.id}>` or `<a href=${item.url}>`, compiled to the fallback renderer, which re-renders every row's HTML on each change. They now use the optimised row path, and an attribute that mixes a signal with item data on an element below the row root is written to that element instead of the row element.
- A developer `id` on a bound element inside a `repeat()` row no longer forces the list onto the fallback renderer; the `id` is kept.
- The build no longer fails with `ENOENT` when emptying an existing output directory given as a `./`-prefixed path under Bun 1.4 on Windows.
- `when()` blocks now compile their content as a full sub-template. Event handlers on elements inside a `when()` block were never bound, a `whenElse()` or `repeat()` inside a `when()` block corrupted the surrounding template (a nested `repeat()` crashed at mount), an event handler inside a `when()` block truncated the content that followed it, and a binding inside a nested `when()` registered a phantom binding on the outer block.
- `whenElse()` initialises nested `when`/`whenElse` blocks from the branch they belong to; the else branch previously received none and the then branch received both.
- Conditions that cannot be evaluated at compile time (local non-signal values, signals without a known initializer) defer branch selection to mount instead of pre-rendering the else branch.
- Runtime helpers used only inside nested directive branches (for example a `when()` inside a `whenElse()` branch) are now imported.
- Child components mounted inside a directive nested in a `whenElse()` else branch are set up by the correct branch initializer.
- `computed()` no longer drops a change notification when another subscriber reads the computed before its deferred notification runs.
- The HTML parser tracks nested object-literal braces inside template-literal expressions.
- Template parse diagnostics no longer call an unbound logger method.
- `when()`, `whenElse()` and nested `repeat()` inside a `repeat()` row now see the row's item and index: conditions, branch templates and inner lists read them through row-scoped signals, so a row updates its nested directives when its item changes. Row event handlers that do not mention the item (a plain function reference, or an arrow that only calls a component function) are attached and called with the event.
- Form and state attributes (`value`, `checked`, `selected`, `disabled`, `open`, `hidden`, `readonly`, `required`, `multiple`, `indeterminate`, `muted`) are written as DOM properties, so `checked=${false}` unchecks and `value=${name()}` moves the field's live value; the static template ships no attribute for a bound boolean. `null` and `undefined` render as empty text instead of the words.
- One attribute grammar: static text around an expression is kept (`class="btn ${kind()}"` writes `btn primary`), `style=${expr}` writes `cssText`, `style="color: ${c()}"` binds the property, and a `:`-prefixed attribute is a build error (THANE006) instead of a literal attribute named `:src`.
- The string fallback row renderer is gone. Every `repeat()` list, including one inside a `when()` or `whenElse()` branch, uses the keyed row path with cloned templates, guarded updates and delegated events. A row template with more than one root element, or none, is a build error (THANE007) that says what to wrap; a row that is only a `whenElse()` is named as such. Rows whose only binding is a component signal were left unbound by the clone-only path; they are bound now.
- Developer `id` attributes are kept on attribute- and style-bound elements and on `whenElse()` branch roots (previously the compiler's id won, or the branch never hid). Generated code refers to such elements through a derived variable, so an id can neither shadow a component variable nor need to be a valid identifier.
- `props.count()` read directly in a template is a tracked signal read, as the Components doc shows; `const count = props.count` is no longer needed.
- `${index}` bindings follow the row: after a reorder or a removal, every row at a new position is refreshed. Lists without an index binding do no extra work.
- The router mounts the route again when only the query changes (`navigate('/a?x=2')` from `/a?x=1`), so `route.searchParams` is current; a hash-only change keeps the instance. Persisting the scroll position no longer rewrites the history entry's URL to the bare pathname, so browser back returns to the full URL.
- Compiler exceptions fail the build with the diagnostic instead of shipping the component uncompiled.

### Changed

- TypeScript updated from 5.9 to 6.0.3, the last release that ships the JavaScript compiler API the Thane compiler and linter are built on. TypeScript 7 (the Go-native compiler) does not expose that API until 7.1 and is not yet a drop-in replacement.
- Toolchain: Bun 1.4.2, esbuild 0.28, Playwright 1.63, Prettier 3.9, `@types/bun` 1.4 and `@types/node` 26.
- Repository layout: documentation lives in `docs/` with the contributing guides under `docs/contributing/`; the benchmark and both store example apps live under `example-apps/`; e2e builds and Playwright output stay under `e2e/`.
- The Thane store example depends on the framework through `bun link` instead of copying the repository into its `node_modules`.
- Compiler: type sync and type checking are scoped to the project that owns the entry point instead of the current working directory, so building from the repository root no longer writes `.thane` folders into unrelated projects.
- The benchmark app depends on `example-apps/benchmark/thane.tgz`, produced by `bun run test:benchmark`, instead of a version-numbered tarball that went stale on every release.
- Documentation: the CLI reference now lists the real flag spellings and the JSON/JSONC config file format; directive docs describe nesting inside `when()` blocks and compile-time branch selection.
